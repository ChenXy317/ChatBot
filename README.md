# QQ 个人号 LLM 拟人化接管

一个运行在本机的 QQ 私聊自动回复系统。它通过 NapCat 接入个人 QQ，使用兼容 OpenAI 接口的大语言模型生成回复，并通过消息合并、分段发送、动态打字延迟和“正在输入”状态，让对话更接近真人聊天。

项目附带 Web 管理控制台，可在浏览器中完成模型配置、好友白名单、QQ 账号登录和消息数据库管理，不需要手动修改数据库。

> 请只在自己有权使用的 QQ 账号和会话中运行。自动回复涉及个人账号使用限制，请自行确认相关服务条款与使用风险。

## 功能

- **私聊自动回复**：只处理白名单好友的一对一私聊，群聊和机器人自己的消息会被忽略。
- **连续消息合并**：好友连续发来多条消息时，系统等待一段可配置的防抖时间，再合并成一次请求。
- **即时打断**：生成回复期间收到新消息，会取消旧任务并重新处理，避免先后回复两轮内容。
- **拟人化发送**：按换行拆成多条消息，显示“正在输入”状态，并根据文字长度调整发送间隔。
- **图文多模态**：读取 QQ 消息中的文字和图片 URL，发送给支持视觉输入的模型。
- **完整历史上下文**：每轮读取数据库中该好友的全部聊天记录，不截断为固定条数。
- **三段式 Prompt**：系统提示词由“角色设定、好友设定、输出设定”三部分组成，块间自动保留空行。
- **消息数据库管理**：在网页中查看任意好友的全部消息，编辑内容或图片 URL，删除单条记录，或清空某位好友的全部记录。
- **账号管理**：查看 QQ 在线状态，扫码登录新账号，快速切换已保存账号，或停止 NapCat。
- **运行诊断**：测试模型接口连通性，查看服务状态、最近事件和异常日志。

## 工作原理

```text
好友发送 QQ 私聊
        │
        ▼
     NapCat
        │ OneBot v11 / 反向 WebSocket
        ▼
 FastAPI 中继服务
        │
        ├─ 检查白名单与总开关
        ├─ 合并连续消息
        ├─ 读取全部历史记录
        ├─ 拼接三段式 System Prompt
        ▼
 兼容 OpenAI 接口的大模型
        │
        ▼
 分段、延迟发送 QQ 消息
        │
        ▼
    MySQL / MariaDB
```

浏览器控制台与中继服务使用同一端口，默认地址为 `http://127.0.0.1:8090`。NapCat 默认通过 `ws://127.0.0.1:8090/ws/qq` 连接中继。

## 快速开始

### 1. 准备环境

需要：

- Windows 10/11 64 位
- Python 3.12 或更高版本
- MySQL 8.0 或 MariaDB
- Windows 桌面版 QQ，以及可正常工作的 NapCat

如果项目目录中已有 `.venv`，启动脚本会自动使用它。没有虚拟环境时，可在项目根目录执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### 2. 准备数据库

创建数据库：

```sql
CREATE DATABASE IF NOT EXISTS qq_chatbot
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;
```

复制环境配置模板：

```powershell
Copy-Item .env.example .env
```

然后编辑 `.env`：

```env
MYSQL_HOST=127.0.0.1
MYSQL_PORT=3306
MYSQL_USER=root
MYSQL_PASSWORD=你的数据库密码
MYSQL_DATABASE=qq_chatbot

SERVER_HOST=127.0.0.1
SERVER_PORT=8090

DASHBOARD_TOKEN=
ONEBOT_WS_TOKEN=
```

配置说明：

| 配置项 | 用途 |
| --- | --- |
| `MYSQL_HOST` | 数据库地址，本机数据库通常填写 `127.0.0.1` |
| `MYSQL_PORT` | 数据库端口，MySQL/MariaDB 默认是 `3306` |
| `MYSQL_USER` | 数据库用户名 |
| `MYSQL_PASSWORD` | 数据库密码，没有密码时留空 |
| `MYSQL_DATABASE` | 使用的数据库名 |
| `SERVER_HOST` | 中继服务监听地址 |
| `SERVER_PORT` | 网页控制台和 WebSocket 共用端口 |
| `DASHBOARD_TOKEN` | 可选的控制台访问口令；留空时不需要登录控制台 |
| `ONEBOT_WS_TOKEN` | 可选的 OneBot 连接口令；留空时自动生成并保存到 `napcat/.onebot_ws_token` |

程序启动时会自动创建缺少的数据表，并兼容旧版配置表。无需手动执行建表 SQL。

### 3. 启动系统

在项目根目录双击 `start.bat`，或在 PowerShell 中执行：

```powershell
.\start.ps1
```

启动脚本会依次：

1. 尝试启动本机 MariaDB。
2. 检查 `8090` 端口是否已有旧版 ChatBot，并在确认属于本项目后安全替换。
3. 修补 QQNT 加载器。
4. 启动 NapCat 并打开登录窗口。
5. 启动中继服务，并自动打开浏览器控制台。

如果已有保存过的账号，脚本会尝试快速登录；没有保存账号时会显示扫码登录。

也可以手动启动后端：

```powershell
.\.venv\Scripts\python.exe main.py
```

### 4. 登录 QQ

使用扫码登录：

1. 打开网页控制台的“账号管理”。
2. 点击“扫码登录新账号”。
3. 使用手机 QQ 扫描弹窗中的二维码。
4. 登录成功后，顶部连接状态会变为绿色。

如果账号之前已在本机登录并允许快速登录，也可以在“快速拉起指定账号”中填写 QQ 号后启动。

### 5. 配置模型

进入“模型与规则配置”，填写：

- **API 基础地址**：兼容 OpenAI Chat Completions 的完整地址，例如 `https://api.deepseek.com/v1` 或自建服务地址。
- **API 密钥**：没有鉴权要求的本地模型可留空。
- **模型名称**：服务端实际支持的模型 ID。
- **防抖时间**：收到消息后等待多久再开始回复，范围 `0.5` 到 `10` 秒。
- **单字耗时**：模拟打字速度，范围 `0.01` 到 `1` 秒。
- **最大生成 Token 数**：限制单次回复长度。
- **采样温度 / Top P**：控制回复随机性与多样性。

保存后立即作用于下一次会话。可使用“连通性测试”检查地址、密钥和模型名称是否正确。

#### Prompt 怎么填写

系统会按以下顺序生成最终的 System Prompt：

```text
角色设定

好友设定

输出设定
```

三块之间自动加一个空行，不添加其他包装文字。

- **角色设定**：机器人自己是谁、身份和基本关系。
- **好友设定**：当前好友是谁、与机器人是什么关系；只对选中好友生效。
- **输出设定**：回复语气、格式、篇幅、禁止事项和当前聊天场景。

好友设定为空时，该段自动省略，角色设定和输出设定之间仍保留空行。

### 6. 添加好友

进入“好友白名单”，点击“添加接管好友”：

1. 填写好友 QQ 号。
2. 填写好友人设，可留空。
3. 点击“确认添加”。

只有启用中的白名单好友会触发自动回复。好友列表中的“编辑”可以修改人设，“移除”会取消该好友的接管资格，但不会自动删除他的聊天记录。

### 7. 管理消息数据库

进入“消息数据库”：

1. 从下拉框选择好友。
2. 页面会加载该好友在数据库中的全部聊天记录。
3. 点击消息旁的“编辑”，可修改文字和图片 URL。
4. 点击“删除”，只删除当前一条记录。
5. 点击“清空当前好友”，删除该好友的全部聊天记录。

这里的修改会直接影响下一次模型读取的上下文。删除或清空后，模型将不再看到对应记录。

## 手动接入 NapCat

如果不使用项目自带的启动脚本，可在 NapCat 中添加反向 WebSocket：

```text
URL: ws://127.0.0.1:8090/ws/qq
重连间隔: 3000 ms
消息格式: array
```

连接口令有两种方式：

- `.env` 中设置了 `ONEBOT_WS_TOKEN`：NapCat 的 token 必须与它一致。
- `.env` 中未设置：程序会生成随机 token，并写入 `napcat/.onebot_ws_token`。NapCat 需要使用该文件中的值。

网页控制台只接受本机访问。即使把 `SERVER_HOST` 改为局域网地址，外部设备也不能访问控制台 API。

## 常见问题

### 网页打不开

检查中继是否在运行：

```powershell
Invoke-RestMethod http://127.0.0.1:8090/api/health
```

正常响应中的 `api_version` 应与当前代码版本一致。若 `8090` 被其他程序占用，启动脚本会拒绝覆盖非 ChatBot 服务。

### 顶部一直显示“NapCat 协议端未连接”

检查：

- NapCat 是否已登录 QQ。
- 反向 WebSocket 地址是否为 `/ws/qq`。
- 端口是否与 `.env` 中的 `SERVER_PORT` 一致。
- NapCat token 是否与 `ONEBOT_WS_TOKEN` 或 `napcat/.onebot_ws_token` 一致。

### 好友发消息但没有自动回复

依次检查：

- 顶部“自动接管”总开关是否开启。
- 好友是否已加入白名单并处于启用状态。
- 模型接口测试是否成功。
- “运行事件与调度日志”中是否有白名单跳过、模型错误或发送错误。
- 好友发的是否为私聊消息；当前版本不处理群聊。

### 回复很慢

回复时间由三部分组成：

1. 防抖等待时间。
2. 模型生成时间。
3. 拟人化发送延迟。

可适当降低“单字输入耗时”和“防抖时间”，或换用响应更快的模型。

### 历史消息过多会不会超过模型上下文

系统会把该好友的全部历史记录发送给模型。普通 QQ 文本消息通常远低于现代大模型的上下文上限；但如果使用小上下文模型、包含大量图片或历史记录特别长，仍可能触发服务端的上下文长度错误。此时可在“消息数据库”中清理不需要的记录。

### 修改了 Prompt 但回复没变化

确认：

- 修改的是当前好友使用的全局配置或好友人设。
- 保存成功且没有报错。
- 新的会话是在保存之后触发的。
- 在“好友白名单”中确认该好友的专属人设没有覆盖你的预期。

## 数据与安全

- `.env`、数据库文件和 NapCat 登录状态不应提交到 Git。
- 数据库中的 `api_key` 不会通过网页接口回显。
- 建议只监听 `127.0.0.1`，不要将控制台直接暴露到公网。
- 聊天记录可能包含隐私信息，删除前请确认不需要保留。
- 删除白名单好友不会自动删除其聊天记录，需要在“消息数据库”中单独清理。

## 项目结构

```text
ChatBot/
├── app/
│   ├── api/                # Web 控制台 REST API
│   ├── core/               # 环境配置与数据库初始化
│   ├── engine/             # 防抖、Prompt、模型调用、拟人化发送
│   ├── gateway/            # OneBot v11 WebSocket 网关
│   ├── models/             # SQLAlchemy 数据模型
│   └── schemas/            # API 请求与响应结构
├── web/                    # 浏览器控制台
├── napcat/                 # NapCat 运行文件
├── scripts/                # 启动前检查与本地数据库辅助脚本
├── tests/                  # 单元测试
├── main.py                 # FastAPI 入口
├── requirements.txt
├── start.bat               # Windows 一键启动
└── start.ps1               # PowerShell 启动
```
